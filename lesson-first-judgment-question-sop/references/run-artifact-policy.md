# 判断题质量门分阶段落盘规则

当用户提供运行目录、要求生成文件，或项目工作流要求保留加工证据时，执行本文件。纯聊天生成不擅自创建持久目录。

## 一、目的

让每道题能够回答：最初怎样生成、在哪道质量门被修改或淘汰、为什么修改、最终版本与原始版本是什么关系。阶段文件是审计证据，不是新的上游题库或术语证据。

## 二、推荐目录

```text
本次运行/
├─ 00_输入证据/
├─ 01_初始生成/
│  └─ 判断题_原始稿.md
├─ 02_术语准入门/
│  ├─ 术语审核报告.json
│  ├─ gate-result.json
│  └─ 判断题_词汇门后.md          # 仅内容改变时生成
├─ 03_课堂顺读门/
│  ├─ 顺读审核报告.json
│  ├─ gate-result.json
│  └─ 判断题_顺读门后.md          # 仅内容改变时生成
├─ 04_自然消歧门/
│  ├─ 消歧审核报告.json
│  ├─ gate-result.json
│  └─ 判断题_消歧门后.md          # 仅内容改变时生成
├─ 05_完整质量门/
│  ├─ 逐题质量门审核.md
│  ├─ gate-result.json
│  └─ 判断题_完整审核后.md        # 仅内容改变时生成
├─ 06_最终交付/

```

目录编号可以适配项目既有结构，但阶段语义和追溯关系不得丢失。

## 三、落盘规则

1. **原始稿必留**：保存进入质量门前的完整候选题，不用最终稿反写。
2. **上一阶段只读**：后一道门只能引用上一阶段，不能覆盖或静默改写旧文件。
3. **有改才出新稿**：质量门发生题干改写、删除或新增时，生成该门后的阶段稿。
4. **无改只记状态**：全部通过且内容未变时，不复制相同题稿；在 `gate-result.json` 记录 `PASS_NO_CHANGE` 并引用实际输入文件作为输出。
5. **稳定题目身份**：每道候选题从初始生成起获得稳定 `item_id`。删除题目只记录 `DROP`，不得把其他题目的内部编号前移；最终显示序号另用 `display_order`。
6. **逐题留痕**：任何 `REVISE` 或 `DROP` 都记录质量门、修改前、修改后、原因和证据。不要保存内部自言自语，只保存可复核结论。
7. **词表只引用**：运行目录只保存 `lesson_lexicon_ref` 和术语审核报告，不复制或沉淀第二份课时标准词表。
8. **最终一致**：学生版、教师版和结构化题包的题目、答案、编号与审核状态必须一致。

## 四、质量门结果

每道关键质量门的 `gate-result.json` 至少包含：

```text
gate_id
gate_name
status = PASS_NO_CHANGE | PASS_WITH_CHANGES | FAIL
input_artifact
output_artifact
kept_item_ids
revised_item_ids
dropped_item_ids
evidence_artifact
```

`PASS_NO_CHANGE` 时，`output_artifact` 可以与 `input_artifact` 指向同一个文件。`FAIL` 时不得生成最终交付。

## 五、逐题修改轨迹

按稳定 `item_id` 汇总：

| item_id | 质量门 | 处理 | 修改前 | 修改后 | 原因 |
| --- | --- | --- | --- | --- | --- |
| J05 | 术语准入门 | REVISE | 大于90°的角都是优角 | 大于90°的角都是钝角 | “优角”无本课准入证据 |

表中的例子只说明记录格式，不表示改写后的数学命题必然通过其他质量门。每次修改后仍须重新验证真值、顺读和消歧。

## 六、完成检查

- 原始稿存在且未被覆盖；
- 每道关键质量门都有结果记录；
- 只有内容发生变化的门生成了新题稿；
- 所有最终题可追溯到稳定 `item_id`；
- 所有删除和改写都有明确原因；
- 运行目录没有复制课时标准词表；
- 最终三层输出相互一致。
